# Сопоставимые муниципалитеты

Решение для онлайн-конкурса СберИндекса 2026, направление «Кластеризация».

Для каждого из 2 068 муниципалитетов России найдены 15 экономически сопоставимых по данным СберИндекса о тратах жителей и по показателям Росстата. Карточка муниципалитета отвечает на три вопроса: где его потенциал (место среди сопоставимых по ключевым показателям), у кого учиться (сопоставимые с наибольшим ростом трат и чем они отличаются) и не уходит ли он от своего типа. Под продуктом — типология на атрибутированной сети муниципалитетов, построенная алгоритмом KEFRiN.

- **Лендинг:** https://polinash-main.github.io/mopeers/ — один файл `site/index.html`, открывается и с диска.
- **Методологический отчёт:** [`report/methodology.md`](report/methodology.md), PDF — `report/methodology.pdf`.
- **Датасет:** `outputs/dataset/` — таблица сопоставимых МО и JSON-карточка на каждый МО, ключ `territory_id` справочника СберИндекса.
- **Снимок исходных данных:** релиз [`data-2026-09-27`](https://github.com/PolinaSh-main/mopeers/releases/tag/data-2026-09-27).

## Результаты

- **Сопоставимые МО дают другой вывод, чем свой регион.** Вывод «траты жителя выше или ниже медианы» меняется у 39% МО, если сравнивать с 15 сопоставимыми, а не со своим регионом. Пример: Чебоксары тратят на 77% больше медианы Чувашии, но среди 16 сопоставимых городов — на 15-м месте.
- **Пять типов локальной экономики:** убывающие районы Центра и Поволжья (590 МО), сельские районы Сибири и Урала (563), города и промышленные центры (469), ресурсные территории (158), мегаполисы и их пригороды (288). Устойчивость на подвыборках — ARI 0,94 в медиане.
- **Выбор числа типов проверен на синтетике.** На 84 атрибутированных сетях с известным ответом (генератор из репозитория KEFRiN) S_Dbw, AVI и AVU непригодны для выбора K; правило Борда по двум равновесным блокам индексов (признаки и сеть) точнее голосования. Нулевая модель подтверждает, что кластерная структура есть.
- **KEFRiN, ξ = 2.** На синтетике — без провалов при слабых признаках и при зашумлённой сети; на реальных данных совпадает с k-средних по признаковым индексам и превосходит его по сетевым (10 запусков на метод).
- **Правило ребра — слияние структуры трат и дорожной близости:** самые однородные соседи и по 30 признакам, и по показателям Росстата, которые в ребро не входят.
- **Динамика 2024 года без общестранового сдвига:** тип сменили 80 МО; флаг расхождения — у 178.
- **Описания типов — интервальные узорные структуры** с проверкой на отложенной половине МО (точность 0,59–1,00).
- **Внешние проверки.** Индекс мобильности СберИндекса различает типы (η² = 0,65). Траты жителя выше там, где больше занятых в малом бизнесе (реестр МСП ФНС, коэффициент Спирмена 0,38). Ночная освещённость со спутника с тратами почти не связана: на уровне МО она отражает промышленность и плотность застройки. Две трети моногородов (116 из 178) типология относит к городам и промышленным центрам, хотя среди всех МО этот тип составляет 23%. Новости 2024 года (2 842 заголовка, разметка открытой моделью Qwen3.5-35B, согласие с ручной разметкой — каппа Коэна 0,68) флаг расхождения не отражают: с поправкой на число заголовков различие групп не значимо.

## Запуск

Нужны [uv](https://docs.astral.sh/uv/) и Node.js (только для шага `geo`: упрощение границ через `npx mapshaper`).

```bash
uv sync
uv run mopeers all          # все шаги по порядку
uv run mopeers --help       # список шагов; любой шаг запускается отдельно: uv run mopeers typology
```

Без uv — обычное виртуальное окружение Python 3.12 и зависимости с зафиксированными версиями:

```bash
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
mopeers all
```

Шаг `download` скачивает исходные данные из официальных источников и проверяет SHA-256 пакета Data Sense. Если источник недоступен, данные берутся из снимка в релизе репозитория (проверка SHA-256); снимок можно взять и принудительно: `MOPEERS_SNAPSHOT=1 uv run mopeers download`. Шаг `data` скачивает из Базы данных показателей муниципальных образований Росстата только нужные показатели и только за 2022–2024 годы (каталог «Точно», чтение отдельных файлов из архивов по HTTP Range). Сторонний код — KEFRiN с генератором синтетических сетей и метрики библиотеки Pattern — скачивается с зафиксированных коммитов репозиториев авторов в `third_party/` и не изменяется.

Полный прогон после скачивания данных занимает около 25 минут на ноутбуке (12 ядер, без GPU). Прогон с нуля в чистой копии репозитория воспроизводит побайтно все таблицы и наборы данных в `outputs/`.

Внешние проверки запускаются отдельно: `mopeers.sme` (реестр МСП; исходный файл 16 ГБ скачивается с data.rcsi.science после регистрации, агрегат по МО — `data/processed/sme.parquet`), `mopeers.nightlights` (ночная освещённость, Zenodo), `mopeers.monotowns` (моногорода и акции градообразующих компаний), `mopeers.news` (новости, разметка языковыми моделями на Kaggle, `kaggle/news_kernel.py`).

## Гиперпараметры

Все параметры — в `configs/base.yaml`: окна признаков, правила рёбер и k соседей, методы и перебор K, вес сети ξ, параметры типологии, синтетики, интерпретации и продукта. Названия и описания типов — `configs/types.yaml`.

## Структура

| Путь | Содержимое |
|---|---|
| `src/mopeers/` | конвейер: `download`, `data`, `rosstat`, `features`, `network`, `cluster`, `synth`, `typology`, `dynamics`, `interpret`, `product`, `geo`, `site`; внешние проверки: `sme`, `nightlights`, `monotowns`, `news` |
| `kaggle/` | ядро Kaggle для новостей и ручная разметка 120 заголовков для проверки моделей |
| `configs/` | гиперпараметры и описания типов |
| `outputs/network/` | сравнение правил рёбер |
| `outputs/cluster/` | сетка ICVI, синтетика, нулевая модель, перебор ξ, методы по сидам |
| `outputs/typology/` | типы, выбор K, устойчивость |
| `outputs/dynamics/` | типы по окнам, переходы, флаг расхождения |
| `outputs/interpret/` | профили типов, интервальные описания, пороговые правила, сверка с категориями, внешние проверки |
| `outputs/dataset/` | продукт: `mo_peers.csv`, `api/<territory_id>.json` |
| `site/` | шаблон и собранный лендинг |
| `report/` | методологический отчёт |
